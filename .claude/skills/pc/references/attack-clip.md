## 클립이란 무엇인가

`Clip` 은 **관절 각도 커브의 묶음**이다. 좌표를 담지 않는다.

```
Clip.sample(t)  →  Pose (각도만)  →  solve(body, pose, yaw:)  →  Skeleton (좌표)
```

이 규약의 대가:

- 하나의 공격 클립이 **8등신 기사와 4등신 고블린 모두**에서 재생된다.
- 캐릭터 치수를 바꿔도 애니메이션을 다시 안 만든다.
- 8방향 회전이 애니메이션 데이터를 건드리지 않는다 — `yaw` 는 `solve` 의 인자다.

**절대 하지 말 것**: 클립 안에서 `Offset` 을 계산하거나 `Body` 치수를 참조하는 것. 그 순간 클립이 특정 체형에 고정된다.

## Clip — 전 필드

**파일: `lib/src/anim/clip.dart`**

### 재생 파라미터

| 필드 | 기본값 | 무엇 |
|---|---|---|
| `name` | 필수 | 코드에서 참조하는 식별자. `play('attack')` 의 그 문자열 |
| `label` | 필수 | 뷰어 버튼에 표시되는 이름 |
| `duration` | 필수 | 한 사이클(루프) 또는 전체 재생(원샷) 길이(초) |
| `loop` | `true` | 루프면 `sampleLoop`(마지막↔첫 키가 이어짐), 원샷이면 `sampleOnce`(0..1 클램프) |
| `blendIn` | `0.18` | 다른 클립에서 넘어올 때의 크로스페이드 시간(초) |
| `autoSeconds` | `3.2` | 뷰어 AUTO 순환에서 이 클립에 머무는 시간 |
| `holdAtEnd` | `false` | 원샷이 끝난 뒤 마지막 포즈를 유지할지. `death` 만 `true`. **끝난 뒤에는 미세 요동까지 멎는다** |
| `repeatDelay` | `0.28` | 원샷을 뷰어에서 자동 반복할 때의 여백 |
| `events` | `const []` | 클립 위의 시점 표식. `Animator.fired` 로 읽는다 → [ClipEvent](#clipevent--판정은-progress-가-아니라-시점으로) |
| `strideCycle` | `0` | 한 사이클이 나아가는 거리 — **다리 길이의 배수**. 0 이면 제자리 동작 → [보폭 동기화](#strideCycle--발-미끄러짐-없애기) |

**`blendIn` 이 입력 반응성을 결정한다.** 공격 0.09 · 피격 0.04 · 사격 0.12 · 루프 클립 0.18(기본). 공격을 0.18 로 두면 버튼을 눌러도 0.18초 동안 이전 자세가 섞여 보여 "굼뜨다"고 느껴진다. **반대로 0 으로 두면 툭 튄다.** 0.06~0.12 가 대역이다.

### 트랙 (전부 `List<double>?`)

| 묶음 | 트랙 | 미지정 시 기본값 |
|---|---|---|
| 루트 | `rootX` `rootY` `rootRot` | 0 · 0 · 0 |
| 척추 | `spine` `chest` `neck` `head` | 0 · 0 · 0 · 0 |
| 근거리 팔 | `nearShoulder` `nearElbow` `nearWrist` | **0.10** · **0.22** · 0 |
| 원거리 팔 | `farShoulder` `farElbow` `farWrist` | **0.08** · **0.20** · 0 |
| 근거리 다리 | `nearHip` `nearKnee` `nearAnkle` | **0.05** · **0.06** · 0 |
| 원거리 다리 | `farHip` `farKnee` `farAnkle` | **−0.05** · **0.08** · 0 |
| 표정·연출 | `breath` `squash` `weaponSwing` `mouth` `eyeOpen` `capeFlow` `impact` | 0 · **1** · 0 · 0 · **1** · 0 · 0 |

**굵은 값이 함정이다.** 트랙을 생략하면 "이전 클립 값 유지"가 아니라 **저 상수로 고정**된다. 상체만 쓰는 공격을 만들면서 다리 트랙을 빼면, 걷다가 공격하는 순간 다리가 레스트 자세로 튄다.

### 각도의 부호 규약

| 관절 | + 방향 | 제약 |
|---|---|---|
| `shoulder` | 팔을 **앞·위**로 든다 | 없음 |
| `elbow` | 굽힘. 손이 앞으로 접힌다 | **항상 0 이상** |
| `wrist` | 무기 각도에 그대로 반영 | 없음 |
| `hip` | 다리를 **앞**으로 내민다 | 없음 |
| `knee` | 굽힘. 정강이가 **뒤**로 접힌다 | **항상 0 이상** |
| `ankle` | 발끝을 든다 | 없음 |
| `rootRot` | 몸 전체가 **앞**으로 기운다 | 없음 |
| `spine` | 허리가 앞으로 숙여진다 | 없음 |
| `rootX` | **전방** 변위 (키 대비 비율) | 없음 |
| `rootY` | **아래**(웅크림). − 가 도약 | 없음 |

`elbow`·`knee` 가 음수면 관절이 해부학적으로 반대로 꺾인다. `example/test/widget_test.dart` 가 `> -0.25` 로 막는다 — 여유 0.25 는 Catmull-Rom 오버슈트 몫이다.

## 보간: 왜 Catmull-Rom 인가

```dart
double _catmull(double p0, double p1, double p2, double p3, double t) => 0.5 *
    ((2 * p1) + (-p0 + p2) * t + (2 * p0 - 5 * p1 + 4 * p2 - p3) * t2
     + (-p0 + 3 * p1 - 3 * p2 + p3) * t3);
```

선형 보간은 관절 **속도**가 키마다 계단처럼 꺾여 로봇으로 보인다. 곡률이 연속인 보간이면 키를 9개만 찍어도 손으로 다듬은 듯한 가감속이 나온다.

**대가는 오버슈트다.** 곡선은 키 값을 지나가되 그 사이에서 **넘어선다**. 인접 키 차이가 크면 클수록 크게 넘는다.

```dart
nearKnee: [0.28, 0.35, 0.42, 0.40, 0.30, 0.26, 0.28, 0.30, 0.28]   // 안전 — 차이 ≤ 0.07
nearKnee: [0.10, 0.10, 1.80, 0.10, ...]                             // 위험 — 사이에서 음수로 내려간다
```

**대책 셋**:
1. 인접 키 차이를 완만하게 — 급변이 필요하면 **중간 키를 하나 더** 넣는다(이것이 히치 키의 부수 효과다).
2. 0 근처를 지나는 굽힘 관절은 하한을 0.05~0.10 로 띄운다.
3. `flutter test` 의 역굽힘 검사를 반드시 통과시킨다.

**루프와 원샷은 다른 샘플러를 탄다.**

```dart
sampleLoop(keys, t)   // n 개 키가 원형으로 이어짐. keys[n-1] → keys[0] 이 연속
sampleOnce(keys, t)   // keys[0] 이 t=0, keys[n-1] 이 t=1. 양 끝은 clamp
```

그래서 **루프 클립에서는 첫 키와 마지막 키가 달라야** 한다(둘 다 순환의 서로 다른 지점). **원샷에서는 같아야** 한다(둘 다 가드 자세).

## 9키 격자 — 원샷의 비트 배치

원샷 클립은 키 `i` 가 `t = i/(n-1)` 에 놓인다. 9키면 0.125 간격이다.

| 키 | t | `Anims.attack`(0.86s) | 역할 | 저작 지침 |
|---|---|---|---|---|
| 0 | 0.000 | 0.00s | **가드** | 키 8 과 **모든 트랙에서** 같게 |
| 1 | 0.125 | 0.11s | 감기 시작 | 체중을 뒤로. 아직 작게 |
| 2 | 0.250 | 0.22s | **예비 정점** | 가장 크게 감은 자세. 여기가 클수록 강해 보인다 |
| 3 | 0.375 | 0.32s | **히치** | 정점에서 아주 조금 되돌린다. 판정 창이 열리는 지점 |
| 4 | 0.500 | 0.43s | **임팩트** | `weaponSwing` 1.0, `squash` 최저, `rootX` 전진 |
| 5 | 0.625 | 0.54s | 오버슈트 | 팔이 임팩트를 지나쳐 뻗는다. `rootX` 최대 |
| 6 | 0.750 | 0.65s | 회복 시작 | 여기서부터 느리게 |
| 7 | 0.875 | 0.75s | 가드 접근 | |
| 8 | 1.000 | 0.86s | **가드** | = 키 0 |

비율: **예비 37.5% / 타격 12.5% / 회복 50%**.

**히치(키 3)가 타격감의 절반이다.** 예비 정점에서 곧장 때리면 기계 팔이다. 정점을 한 키 유지하며 아주 조금 되돌리면 — `nearShoulder` 2.65 → 2.55 — 근육이 힘을 모으는 것으로 읽힌다. 물리적으로도 맞다: 사람은 최대 각도에 도달한 뒤 반동을 준 다음 휘두른다.

**임팩트를 키 4(정중앙)에 두는 이유**는 판정 창 계산이 단순해지기 때문이다. `progress >= 0.375` 하나로 창이 열린다.

### 더 긴 동작 — 키를 늘리는 법

9키로 부족하면 **13키**(간격 0.0833)를 쓴다. 비트가 이렇게 떨어진다.

| 키 | t | 역할 |
|---|---|---|
| 0 | 0.000 | 가드 |
| 4 | 0.333 | 예비 정점 |
| 5 | 0.417 | 히치 |
| 6 | 0.500 | 임팩트 |
| 7 | 0.583 | 오버슈트 |
| 12 | 1.000 | 가드 |

**짝수 키 개수를 쓰지 않는다** — 임팩트가 키 사이에 놓여 오버슈트 지점이 흐려진다.

## `Anims.attack` 트랙별 해부

19개 트랙이 하나의 동작을 만든다. 각 트랙이 왜 저 모양인지가 곧 저작 지침이다.

```dart
rootX:  [0, -0.010, -0.020, -0.022, 0.040, 0.055, 0.048, 0.020, 0]
```
**체중 이동.** 감을 때 뒤로(−0.022), 때릴 때 앞으로(+0.040), **오버슈트에서 최대**(+0.055). 임팩트 키가 아니라 그 다음 키에서 최대인 것이 핵심 — 몸이 칼을 따라 끌려간다. 이 트랙이 없으면 상체만 흔드는 허수아비가 된다.

```dart
rootY:  [0.02, 0.026, 0.032, 0.034, 0.010, 0.016, 0.022, 0.022, 0.02]
```
**높이.** 감을 때 낮아지고(웅크림, +0.034) 때릴 때 솟는다(+0.010). 다리를 펴며 힘을 전달하는 모습이다.

```dart
rootRot:[0.08, -0.06, -0.14, -0.15, 0.22, 0.30, 0.24, 0.12, 0.08]
spine:  [0.03, -0.10, -0.20, -0.22, 0.18, 0.26, 0.20, 0.08, 0.03]
chest:  [-0.02, -0.10, -0.16, -0.17, 0.10, 0.16, 0.12, 0.02, -0.02]
```
**세 축의 같은 방향 누적.** 감을 때 셋 다 음수(뒤로 젖힘), 때릴 때 셋 다 양수(앞으로 던짐). 부호 전환의 크기가 위→아래로 갈수록 작아진다(0.45 → 0.40 → 0.27) — **골반이 먼저 돌고 흉곽이 따라간다.** 이 순서를 뒤집으면 상체로만 치는 것처럼 보인다.

```dart
head:   [-0.05, 0.02, 0.08, 0.08, -0.10, -0.16, -0.12, -0.07, -0.05]
```
**머리는 몸의 반대다.** 몸이 뒤로 젖혀질 때 머리는 앞을 본다(+0.08) — 목표에서 눈을 떼지 않는다. 임팩트에서 아래를 향한다(−0.16). 이 반대 위상이 캐릭터에게 **의도**를 준다.

```dart
nearShoulder: [1.30, 2.10, 2.65, 2.55, 0.85, 0.35, 0.30, 0.70, 1.30]
nearElbow:    [0.55, 0.95, 1.35, 1.45, 0.35, 0.15, 0.30, 0.55, 0.55]
nearWrist:    [0.20, 0.50, 0.90, 1.00, -0.20, -0.35, -0.20, 0.10, 0.20]
```
**때리는 팔.** 어깨 1.30 → 2.65(머리 뒤로) → 0.35(완전 전개). 어깨보다 팔꿈치가, 팔꿈치보다 손목이 **한 키 늦게** 정점에 닿는다(어깨 키 2, 팔꿈치·손목 키 3). 이것이 **채찍 순서(whip)** 다 — 몸통 → 어깨 → 팔꿈치 → 손목으로 힘이 전달된다. 순서를 맞추지 않으면 팔 전체가 한 덩어리로 도는 통나무가 된다.

```dart
farShoulder: [0.85, 0.70, 0.55, 0.55, 1.25, 1.45, 1.35, 1.05, 0.85]
farElbow:    [1.10, 1.25, 1.40, 1.40, 0.95, 0.80, 0.90, 1.05, 1.10]
```
**반대 팔은 반대 위상이다.** 때리는 팔이 감길 때 펴지고, 때릴 때 접힌다. 균형을 잡는 것이며 **없으면 한쪽만 움직이는 마네킹**이 된다.

```dart
nearHip: [0.15, 0.05, -0.02, 0.00, 0.35, 0.42, 0.38, 0.25, 0.15]
farHip:  [-0.12, -0.05, 0.02, 0.00, -0.30, -0.38, -0.34, -0.22, -0.12]
farKnee: [0.30, 0.26, 0.22, 0.24, 0.45, 0.55, 0.50, 0.38, 0.30]
farAnkle:[-0.05, 0.00, 0.05, 0.05, -0.25, -0.35, -0.30, -0.15, -0.05]
```
**보폭이 벌어진다.** 임팩트에서 앞다리 +0.42 / 뒷다리 −0.38 → 스탠스가 0.80 라디안만큼 넓어진다. 뒷다리 무릎이 굽고(0.55) 발끝이 눌린다(−0.35) — 땅을 밀고 있다. **다리로 치지 않는 공격은 팔 운동이지 공격이 아니다.**

```dart
weaponSwing: [0, 0, 0.20, 0.45, 1.0, 0.80, 0.40, 0.10, 0]
squash:      [1, 1.005, 1.01, 1.01, 0.985, 0.99, 1.0, 1.0, 1]
mouth:       [0, 0.15, 0.35, 0.45, 0.70, 0.45, 0.20, 0.05, 0]
```
`weaponSwing` 은 **키 4 에서만 1.0** — 궤적이 한 프레임에 집중돼야 속도가 읽힌다.
`squash` 는 감을 때 늘어나고(1.01) 때릴 때 눌린다(0.985). 폭은 **±1.5% 면 충분하다** — 0.9 같은 값을 넣으면 만화가 된다.
`mouth` 는 임팩트에서 0.70 — 기합. 얼굴이 안 보이는 뒷모습에서도 비용이 0 이므로 넣어 둔다.

**적혀 있지 않은 트랙**: `neck` · `farWrist` · `nearAnkle` · `breath` · `eyeOpen` · `capeFlow` · `impact`.
그중 **`capeFlow` 가 0 인 것은 개선 여지다** — 망토를 두른 PC 가 돌진하며 벨 때 천이 가만히 있다. 예비에서 0.2, 임팩트에서 0.8, 회복에서 0.3 정도의 커브를 얹으면 실루엣이 살아난다.

## 트랙 우선순위 — 무엇부터 적는가

공격 하나를 만들 때 19개를 한꺼번에 채우지 않는다. **순서대로 얹으며 매번 뷰어에서 확인한다.**

| 순위 | 트랙 | 없으면 |
|---|---|---|
| 1 | `nearShoulder` `nearElbow` | 팔이 안 움직인다 — 공격이 아니다 |
| 2 | `weaponSwing` | 무기가 안 눕고 궤적이 없다 |
| 3 | `rootX` `rootRot` `spine` | 상체만 흔드는 허수아비 |
| 4 | `nearHip` `farHip` `farKnee` | 다리로 안 치는 팔 운동 |
| 5 | `nearWrist` | 채찍 순서의 마지막 마디가 빠져 통나무처럼 돈다 |
| 6 | `farShoulder` `farElbow` | 한쪽만 움직이는 마네킹 |
| 7 | `chest` `head` | 의도가 안 읽힌다 |
| 8 | `squash` `rootY` `farAnkle` | 무게가 없다 |
| 9 | `mouth` `capeFlow` | 마감 |

**1~4 까지만 있어도 공격으로 읽힌다. 5~7 이 AAA 와 무료 에셋을 가른다.**

## `ClipEvent` — 판정은 `progress` 가 아니라 시점으로

```dart
class ClipEvent {
  const ClipEvent(this.name, this.at);
  final String name;    // 게임 쪽에서 비교하는 식별자
  final double at;      // 클립 안의 정규화 시각 0..1
}
```

히트박스·사운드·이펙트를 "몇 번째 프레임"이 아니라 **클립의 어느 지점**에 건다. 프레임률이 흔들려도, 보폭 동기화로 배속이 바뀌어도 언제나 같은 자세에서 정확히 한 번 터진다.

```dart
static const attack = Clip(
  …,
  // weaponSwing 이 최대인 지점. 판정·타격음·궤적이 전부 이 한 시점을 본다.
  events: [ClipEvent('strike', 0.5)],
);
```

읽는 쪽:

```dart
if (actor.animator.fired.contains('strike')) { … }
```

`Anims` 가 이미 들고 있는 이벤트:

| 클립 | 이벤트 | 시각 |
|---|---|---|
| `attack` | `strike` | 0.5 (키 4 — `weaponSwing` 정점) |
| `shoot` | `release` | 0.5 (시위를 놓는 프레임) |
| `hit` | `impact` | 0.0 (첫 프레임이 가장 크다) |
| `death` | `collapse` | 0.5 (무릎이 꺾여 무게가 넘어가는 지점) |
| `walk` `run` `dash` | `footfall` ×2 | 0.0 · 0.5 |

**규칙 셋**

1. **`weaponSwing` 정점과 같은 시각에 둔다.** 어긋나면 칼이 닿기 전에 피가 튀거나, 지나간 뒤에 튄다.
2. **경계는 반열림 `(from, to]`.** `Animator._collect` 의 규약이다. 양끝을 다 포함하면 프레임 경계에 걸린 이벤트가 두 번 터지고, 다 빼면 배속이 낮을 때 영영 안 터진다.
3. **루프 클립의 이벤트는 사이클마다 터진다.** `walk` 를 두 사이클 돌리면 `footfall` 이 4번이다.

## `strideCycle` — 발 미끄러짐 없애기

```dart
/// 한 사이클이 나아가는 거리 — 다리 길이의 배수.
final double strideCycle;
```

**길이를 픽셀이나 타일이 아니라 다리 길이로 적는다.** 클립 데이터가 관절 각도만 담는다는 규약과 같은 이유다 — 다리가 짧은 몬스터와 8등신 영웅이 같은 클립을 써도 각자의 보폭으로 걷는다.

값의 근거는 클립의 고관절 스윙이다.

| 클립 | 고관절 스윙 | 계산 | `strideCycle` |
|---|---|---|---|
| `walk` | +0.50 … −0.45 | 한 걸음 `2·L·sin(0.95/2) ≈ 0.92·L`, 사이클은 두 걸음 | **1.83** |
| `run` | +0.72 … −0.75 | 한 걸음 ≈ 1.34·L, 체공이 보폭을 30% 더 벌린다 | **3.5** |
| `dash` | +0.95 … −1.05 | 체공이 보폭을 지배한다 | **4.7** |
| `attack` `hit` `shoot` `idle` `wait` `death` | — | 제자리 동작 | **0** (미지정) |

`RiggedIsoActor` 가 이 값으로 재생 배속을 정한다.

```dart
double cycleTiles(Clip c) {
  final legPx = body.legLength * (height / body.height);   // 화면상 다리 길이
  return c.strideCycle * legPx / iso.worldScale;           // 타일 단위로
}
double _rateFor(Clip c, double speed) {
  final cycle = cycleTiles(c);
  if (cycle <= 1e-6) return 1.0;                            // 제자리 동작은 그대로
  return (c.duration * speed / cycle).clamp(0.55, 1.9);
}
```

**공격 클립에 `strideCycle` 을 넣지 않는다.** 넣으면 빨리 걷다가 공격할 때 칼이 빨리 나가 **판정 타이밍이 이동 속도에 따라 달라진다.**

**클램프 `0.55~1.9` 의 이유**: 대역을 열어 두면 극단에서 클립이 무너진다. 걷기를 두 배로 돌리면 종종걸음이 되고, 절반으로 돌리면 발이 공중에 멎는다. 그 밖의 속도는 **클립을 하나 더 만들어야 한다** — 이것이 `walk`/`run`/`dash` 세 단계가 있는 이유다.

## 렌더러가 읽는 세 트랙

`HumanoidRenderer` 가 포즈에서 직접 읽어 그림을 바꾸는 것은 셋뿐이다.

### `weaponSwing` — 무기 각도와 궤적

`_weapon()` 에서:

```dart
final up = (sk.chest - sk.pelvis).normalized();      // 몸의 수직축
final swing = sk.pose.weaponSwing.clamp(0.0, 1.0);
final pole = lerpO(up, handDir, 0.20 + 0.62 * swing).normalized();   // 장병기
final edge = lerpO(lerpO(up, handDir, 0.62), handDir, swing);        // 도검
```

**왜 손 방향을 그대로 안 쓰는가**: 팔을 내린 순간 손은 아래를 가리키므로, 신장 절반짜리 칼날이 지면을 뚫는다. 그래서 쉴 때는 몸의 수직축에 가깝게 세워 쥐고, **`weaponSwing` 이 오를수록 손을 따라간다.**

결과: **`weaponSwing` 커브가 곧 무기의 눕는 커브다.** 0 → 1 로 급하게 올리면 칼이 튀고, 완만하면 무겁게 휘둘러진다. 대검은 키 2 부터 서서히(0.1 → 0.3 → 0.6 → 1.0), 단검은 키 3 까지 0 이다가 키 4 에 1.0.

`_fx()` 에서는 임팩트 잔상을 그린다 — 손 기준 1.5 라디안 부채꼴, 굵기 `_h * 0.030 * weaponSwing`, `BlendMode.plus`, `pal.glow` 를 흰색과 섞은 색. **0.02 이하면 아예 안 그린다.**

### `impact` — 피격 섬광

```dart
if (p.impact > 0.02) { /* sk.bounds 전체에 주황 RadialGradient · BlendMode.plus */ }
```

**맞은 쪽의 트랙이다.** `Anims.hit` 이 `[1.0, 0.85, 0.55, 0.30, 0.12, 0.04, 0, 0, 0]` 으로 쓴다 — **첫 키가 최대**이고 급감한다. 충격은 예비가 없다.

### `capeFlow` — 천의 뒤흐름

0(정지) ~ 1(전력 질주). `walk` 0.18 · `run` 0.66~0.78 · `dash` 1.0. 공격은 현재 0 이다.

`WeaponKind` 별로 같은 9키 격자에 다른 숫자를 넣는다. **`duration` 과 예비 크기가 무게를 만든다.**

| 무기 | duration | 예비 정점 `nearShoulder` | `weaponSwing` 상승 | 특징 |
|---|---|---|---|---|
| `sword` | 0.86 | 2.65 | 키 2 부터 완만 | 표준. `Anims.attack` 그대로 |
| `greatsword` | 1.10~1.20 | 2.9 이상 | 키 2 부터 아주 완만 | 회복을 55% 로. `rootX` 오버슈트 0.08 |
| `axe` | 0.95 | 2.8 | 키 3 에 급상승 | 위→아래 궤적. `spine` 진폭을 키운다 |

| `daggers` | 0.30~0.35 | 1.8 | 키 4 에만 | 예비 25% / 타격 12% / 회복 63%. 회복이 곧 다음 입력 창 |

- **무거울수록 `duration` 을 늘리고 회복 비율을 키운다.** 예비만 늘리면 굼뜰 뿐 무겁지 않다.

`beast: true` 인 액터는 `_weapon()` 이 즉시 반환한다 — **짐승의 무기는 발톱과 이빨이다.** 짐승형 공격은 무기 궤적 대신 `rootX` 돌진(0.09 이상)과 `mouth`(1.0)로 만든다.

## Animator — 전환과 요동

**파일: `lib/src/anim/animator.dart`**

```dart
final a = Animator(clips: [...]);   // 비우면 Anims.all
a.play(Anims.attack);               // Clip 직접
a.playByName('attack');             // 이름 — 자기 clips 를 먼저, 없으면 Anims.all
a.byName('attack');                 // 같은 탐색을 재생 없이
a.update(dt);
final pose = a.pose;                // 이 프레임의 포즈 (전환 중이면 두 클립의 혼합)

a.speed = 0.25;                     // 사람이 조작하는 배속 — 전환에도 함께 걸린다
a.rate = 1.4;                       // 보폭 동기화 — 클립 시간에만 걸린다
a.progress;                         // 0..1. 루프는 % 1.0, 원샷은 clamp

a.hitstop(0.06);                    // 타격 프레임에서 시간을 멈춘다
a.frozen;                           // 멈춰 있는가
a.fired;                            // 이번 프레임에 지나간 이벤트 이름들
```

### `speed` 와 `rate` 를 나눈 이유

성격이 다르다. **슬로모션(`speed`)은 전환까지 느려져야** 정작 보려던 것을 놓치지 않고, **보폭 동기화(`rate`)는 전환 시간을 건드리면 안 된다** — 빨리 걷는다고 걷기→대기 전환이 짧아질 이유가 없다.

```dart
final ds = dt * speed;      // 사람이 인지하는 시간 — 전환 · AUTO
final d  = ds * rate;       // 클립 위상 시간
```

### `hitstop` 의 정밀도

```dart
if (_freeze >= dt) { _freeze -= dt; return; }
dt -= _freeze; _freeze = 0;       // 남은 정지가 짧으면 나머지로 진행한다
```

남은 정지를 통째로 삼키면 0.06초가 프레임 경계에 따라 0.05~0.08초로 들쭉날쭉해져 **같은 공격의 회복 타이밍이 매번 달라진다.** 겹쳐 부르면 더 긴 쪽이 이긴다.

### `dt` 상한

```dart
if (dt > kMaxFrameStep) dt = kMaxFrameStep;    // 1/20 초 = 60fps 세 프레임
```

프레임이 한 번 크게 밀리면(에셋 로드·GC·창 전환·브레이크포인트) 그 `dt` 를 그대로 먹은 애니메이션은 **예비 동작을 통째로 건너뛰고 타격 자세에서 순간이동한다.** 잘라 두면 최악의 경우 잠깐 느려질 뿐이다. 1/20 보다 짧게 잡으면 30fps 기기에서 상시 슬로모션이 되고, 길게 잡으면 히치 한 번에 동작이 건너뛴다.

세 가지를 더 안다.

**① 같은 클립 재요청의 의미가 다르다.**

```dart
void play(Clip clip) {
  if (identical(clip, _current)) {
    if (!clip.loop) { _time = 0; _restWait = 0; }   // 원샷은 처음부터 다시
    return;                                          // 루프는 위상 유지
  }
  …
}
```

루프가 위상을 유지하는 이유: 걷기 중에 매 프레임 `play('walk')` 를 불러도 걸음이 안 끊기게. 원샷이 되감기는 이유: 공격 버튼을 다시 누르면 다시 휘둘러야 하니까. **연타를 막고 싶으면 호출부에서 `state` 로 거른다** — 애니메이터는 막지 않는다.

**② 전환은 smoothstep 크로스페이드이고, 전환 중 전환도 안전하다.**

이전 클립도 계속 시간이 흐른다(`_fromTime += d`) — 걷다가 공격하면 다리가 걷던 흐름을 유지한 채 섞인다.

```dart
if (_blend < 1) {
  _fromPose = _blended();   // 나가던 클립이 아니라 **지금 화면에 있는** 혼합 포즈
  _from = null;
}
```

전환 도중 또 전환이 걸리면 섞여 있던 결과에서 잇는다. 이것이 없으면 A→B 도중 C 를 누를 때 **A 로 되돌아갔다가 C 로 가는 것처럼** 보인다 — 연타할 때마다 눈에 띈다.

**`Pose.lerp` 는 전 필드 선형 보간이므로, 각도가 π 를 넘나드는 전환에서는 관절이 한 바퀴 돈다.** 그런 경우만 호출부에서 `lerpAngle` 로 따로 처리한다.

**③ 모든 포즈에 저주파 요동이 얹힌다 — 단, 시체는 예외다.**

```dart
Pose _liven(Pose p) {
  // 되돌아오지 않는 동작이 끝나면 요동도 멎어야 한다.
  if (_current.holdAtEnd && _blend >= 1 && _time >= _current.duration) return p;
  final amp = _current.loop ? 1.0 : 0.35;    // 원샷은 진폭을 낮춘다
  return p.copyWith(head: p.head + idleJitter(clock, 0.0, 0.018 * amp), …);
}
```

`clock` 은 클립 시간과 **따로** 흐르므로 클립을 바꿔도 요동이 안 끊긴다. 원샷에서 0.35배로 줄이는 이유: 공격은 의도된 동작이라 요동이 크면 흔들려 보인다. **`death` 가 끝나면 완전히 멎는다** — 시체가 계속 어깨를 들썩이면 죽은 것으로 안 보인다.

**④ 루프 시간은 한 사이클 안으로 되감긴다.**

```dart
double _wrap(Clip c, double t) =>
    (!c.loop || t < c.duration) ? t : t - c.duration * (t / c.duration).floorToDouble();
```

몇 시간을 돌려도 부동소수 정밀도가 유지되고 이벤트 시각 계산이 커지지 않는다. **원샷은 되감지 않는다** — 끝났다는 사실 자체가 상태이기 때문이다(`progress >= 1.0` 이 자동 복귀 조건이다).

## 흔한 실패

| 증상 | 원인 | 처방 |
|---|---|---|
| 클립을 만들었는데 idle 이 나온다 | 재생기가 이름을 못 찾음 | `Anims.all` 또는 `Animator(clips:)` |
| 판정이 안 터진다 | `events` 없음 | `ClipEvent('strike', 0.5)` |
| 판정과 그림이 어긋난다 | 이벤트 시각 ≠ `weaponSwing` 정점 | 같은 시각으로 |
| 판정이 두 번 터진다 | 이벤트를 같은 이름으로 두 번 찍음 | 하나만 |
| 빨리 걸으면 공격도 빨라진다 | 공격에 `strideCycle` 을 넣음 | 제자리 동작에서 뺀다 |
| 발이 얼음판처럼 미끄러진다 | 이동 클립에 `strideCycle` 누락 | 고관절 스윙에서 계산해 넣는다 |
| 극단 속도에서 걸음이 무너진다 | `rate` 클램프(0.55~1.9) 밖 | 클립을 하나 더 만든다 |
| 창 전환 뒤 동작이 건너뛴다 | `kMaxFrameStep` 제거 | 상한을 지우지 않는다 |
| 연타할 때 포즈가 튄다 | 전환 중 전환에서 원본으로 되돌아감 | `_fromPose` 경로 확인 |
| 시체가 어깨를 들썩인다 | `holdAtEnd` 미설정 | `holdAtEnd: true` |
| 클립이 한 프레임도 안 보인다 | 이름이 원샷 4종이 아님 | 이름 변경 또는 `_isOneShot` 확장 |
| 끝나며 툭 튄다 | 키 0 ≠ 마지막 키 | 모든 트랙의 양 끝을 맞춘다 |
| 걷다가 공격하면 다리가 튄다 | 다리 트랙 생략 → 기본값 스냅 | 다리 트랙도 적는다 |
| 무릎이 반대로 꺾인다 | Catmull-Rom 오버슈트 | 인접 키 차이를 줄이거나 하한을 띄운다 |
| 파츠가 통째로 사라진다 | 커브에 NaN | `flutter test` 가 잡는다. 키 배열 길이·타입 확인 |
| 팔이 통나무처럼 돈다 | 어깨·팔꿈치·손목이 동시에 정점 | 한 키씩 늦춘다 (채찍 순서) |
| 상체만 흔드는 허수아비 | `rootX`·`rootRot`·다리 트랙 없음 | 우선순위 3~4 를 채운다 |
| 한쪽만 움직이는 마네킹 | `farShoulder`·`farElbow` 없음 | 반대 위상으로 넣는다 |
| 만화처럼 늘어난다 | `squash` 진폭 과다 | ±1.5% 대역 |
| 궤적이 뭉개진다 | `weaponSwing` 1.0 이 여러 키 | 한 키만 |
| 칼끝이 지면을 뚫는다 | `weaponSwing` 이 쉬는 구간에 0 이 아님 | 가드 구간을 0 으로 |
| 무겁게 만들려 했는데 굼뜨기만 하다 | 예비만 늘림 | 회복 비율을 함께 키운다 |
| 입력이 늦게 반응한다 | `blendIn` 이 큼 | 공격 0.09 이하 |
| 전환이 툭 끊긴다 | `blendIn` 이 0 | 0.05 이상 |
| 뷰어에 버튼이 없다 | `Anims.all` 미등록 | 등록 |
